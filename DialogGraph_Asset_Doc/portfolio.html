✦ Core Features

Everything a narrative game
needs, built for Unity

Six integrated systems covering authoring, runtime, data portability, action scripting, history, and AI-assisted generation.

🗂
Graph-Based Authoring
Author Start, Dialog, Choice, Action, and End nodes in a visual GraphView editor. Connect branches with drag-and-drop edges, inspect each node inline, and build complex narratives without writing JSON manually.
▶
Runtime Playback UI
A TextMeshPro-backed runtime panel handles speaker names, portraits, typewriter text effects, autoplay, skip, and branching choice buttons — all configurable from settings without touching code.
🔄
JSON Round-Trip Workflow
Export any graph to JSON for backup, review, or external editing. Re-import the file directly into the graph editor. The same JSON format drives the AI generation pipeline.
⚡
Action Nodes
Run UnityEvent bindings or coroutine-based gameplay handlers at any point in a dialogue. The DialogActionRunner and IActionHandler interface keep gameplay logic cleanly separated from dialogue data.
📜
History & Transcripts
A player-facing history panel keeps a running backlog of lines played. The transcript system deterministically reconstructs the exact branch the player took — useful for save systems, analytics, and QA.
🤖
AI Generation Layer
An optional editor extension generates candidate graph JSON from structured scene specifications using a provider-backed API. Reviewable before import — it speeds up content authoring without locking you into AI output.
🧩 Node System

Five node types.
One coherent graph model.

Every node has a clearly defined responsibility. The graph stays readable at scale because each type owns exactly one concern.

Node Type Role Key Properties
Start Node Entry point of the graph — one per dialogue asset dialogID mapping, initial state
Dialog Node Displays a line of dialogue with speaker and portrait speakerName, portrait, text, audio clip
Choice Node Presents selectable options that branch the graph choices[], output port per choice
Action Node Fires gameplay logic mid-conversation without blocking UI actionID, waitable flag, IActionHandler
End Node Terminates the dialogue and fires completion events onComplete callback, auto-close option

Runtime Components
DialogManager
Central runtime controller. Loads a graph asset by dialogID, traverses the node graph, fires events, and coordinates the UI layer. Entry point for all gameplay code.
DialogUIController
Drives the TMP-backed panel for speaker names, portraits, typewriter text, autoplay timing, skip input, and choice button layout. Fully decoupled from graph logic.
DialogActionRunner
Resolves action node IDs at runtime, dispatches to registered IActionHandler implementations, and supports both synchronous UnityEvents and awaitable coroutine handlers.
HistoryController
Maintains a player-facing backlog of all lines played in the session. The transcript builder uses this log to reconstruct the exact branch path for saving, analytics, or QA.
GraphSerializer
Handles bidirectional JSON serialization of the graph data model. Used by both the editor export/import tools and the AI generation pipeline's import endpoint.
SettingsModel
Centralized configuration for typewriter speed, autoplay delay, portrait positioning, and UI theme values. Loaded at runtime from a ScriptableObject — no hardcoded values.

GameplayTrigger.cs 
// Trigger a conversation from gameplay code.
// The dialogID maps to a graph asset in Resources.
public class NpcInteract : MonoBehaviour
{
    [SerializeField]
    private string dialogID = "intro_npc_01";

    private void OnInteract()
    {
        DialogManager.Instance
            .Play(dialogID, OnDialogComplete);
    }

    private void OnDialogComplete()
    {
        // Dialogue finished — resume gameplay.
        GameState.SetFlag("met_intro_npc", true);
    }
}
Integration in three lines
Triggering a dialogue from gameplay requires no direct reference to nodes, assets, or serialized data. The dialogID string is the only coupling point between game code and the dialogue system — keeping both sides independently maintainable.

IActionHandler.cs 
/// Implement this interface to handle action nodes.
/// Register your handler with DialogActionRunner.
public interface IActionHandler
{
    /// The actionID this handler responds to.
    string ActionID { get; }

    /// Called when the action node is reached.
    /// Return a coroutine to make it waitable.
    IEnumerator Execute(ActionContext context);
}

// Example implementation:
public class SpawnItemAction : IActionHandler
{
    public string ActionID => "spawn_item";

    public IEnumerator Execute(ActionContext ctx)
    {
        SpawnItem(ctx.GetParam("itemID"));
        yield return null;
    }
}
